Slide 5 — The ML Model
On screen:

Input Features (per team):

Offensive/Defensive efficiency ratings
FG%, 3PT%, FT%
Rebounds, assists, steals, blocks, turnovers (per game)
Turnover ratio, effective FG%, offensive rebound %
Home court advantage flag
Model: Binary classifier → Home win (1) or Away win (0)

Key insight: Tempo-free stats (per-possession) are more predictive than raw totals 2

Say (~1:30):

"The model takes each team's season averages — things like points per game, shooting percentages, rebounding, turnovers — and computes the difference between the two teams. It also factors in home court advantage. These features are fed into a binary classifier that outputs whether the home team wins or loses. I focused on tempo-free statistics where possible, because research shows these are more predictive than raw box score numbers — they normalize for pace of play, so a team that plays slow isn't penalized compared to a team that plays fast. The model runs in real-time on each page load, which created some interesting performance challenges I'll talk about."

Slide 8 — Challenges & Lessons Learned
On screen:

Performance — Enriching 5,000 games with predictions = too slow → Paginate first, predict only 50
Tailwind v4 — New @source directive; classes not compiling until paths were configured
Data quality — Some teams have null stats → defensive try/except around predictions
Full-stack complexity — Django ORM, ML pipeline, responsive UI, JS search — all connected
Say (~30s):

"The biggest technical challenge was performance. Originally the results page tried to run the ML model on every completed game at once — thousands of predictions on a single page load. The fix was to paginate the raw database query first, then only enrich the current page's 50 games. Search uses a lightweight AJAX endpoint that queries the database directly without running predictions. I also ran into Tailwind v4 compilation issues, null data edge cases, and the general challenge of keeping a full-stack app coherent across the backend, ML layer, and frontend."
